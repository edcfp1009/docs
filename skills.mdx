## Three layers, not one

The MCP Server today gives your AI client **tools**: individual actions like tracking, quoting, booking, and importing, documented in [Available Tools](/tools/overview). Tools answer "what can be called." On their own, a new user, or a new AI client, still has to work out FreightPOP's conventions through trial and error.

Two more layers close that gap:

**Skills** are FreightPOP know-how packaged as instructions, not new tools. A skill teaches the AI client how to use the tools it already has: which fields matter for LTL vs. parcel, when to validate an address before quoting, how to read a rate response. Skills answer "how a FreightPOP expert would do this."

**Workflows** are ready-made, multi-step recipes for a specific job, end to end. Instead of asking the AI client to improvise a sequence of tool calls, a workflow chains the right steps in the right order and pauses for confirmation before anything that changes data. Workflows answer "do this whole job for me."

## Why this matters for onboarding

- **Faster first success.** A Skill can bundle the MCP connector together with FreightPOP's conventions in a single install, so a new client's first session already knows how FreightPOP works instead of relearning it prompt by prompt.
- **Fewer support tickets.** A Workflow encodes the checks support already tells people to run (validate before booking, confirm before charging), so mistakes get caught before they become a ticket.
- **Consistency across clients.** The same Skill and Workflow definitions work whether your team is in Claude, ChatGPT, or another MCP-compatible client.

## What we're building toward

- **A FreightPOP plugin for Claude**, bundling the MCP connector with onboarding Skills, so adding FreightPOP also teaches your AI client FreightPOP's conventions in one step.
- **A knowledge pack** for clients without plugin support (ChatGPT, Cursor, and others), added as project or custom-GPT context alongside the connector.
- **Starter Workflows** for the highest-volume jobs teams already do by hand, for example:
  - **Book the cheapest compliant rate:** validate address → get rates → filter by transit time and carrier rules → confirm → book.
  - **Track and flag exceptions:** pull tracking on open shipments → flag anything past its expected delivery window → draft a carrier follow-up.
  - **Import and reconcile an order:** import the order → validate packaging → confirm against the order's ship-by date.
